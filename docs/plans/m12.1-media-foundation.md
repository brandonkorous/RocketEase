# M12.1 — Media pipeline foundation

Execution plan. Architecture: `docs/media-generation.md`. Model layer: `docs/media-models.md`.
Evidence: `docs/research/ai-media-2026.md`.

**Scope:** the plumbing every later stage stands on, plus the beta gate — and, on its own merits, a
fix for a live defect in video publishing. **No generative vendor is called in this stage.** The mock
adapter drives the whole loop end to end, exactly as `PROVIDERS_ENABLE_MOCK=1` does for networks.

---

## 1. Goal, and the defect it closes

`asset-process.ts:45` handles images only. A video upload gets a checksum and a byte count — no
duration, no dimensions, no poster frame. So `Capabilities.limits.videoMaxSeconds` and
`videoMaxBytes` are validated against a duration we never learn, and a 5-minute clip queues happily
for a network that caps at 60s. That fails at the provider, after the publish job has started, which
is the worst place to find out.

**Done means:** an uploaded video is probed, gets a poster frame, and a too-long clip is blocked in
the composer with a reason — plus a mock generation job runs queued → succeeded → asset-in-library
with full lineage and cost captured.

### Non-goals for 12.1

No real model calls, no `AdPlan`, no compositing, no captions, no music, no C2PA signing, no
composer UI beyond what proves the loop. Those are 12.2–12.5. Resist scope creep here; this stage is
worth shipping precisely because it is small and unblocks everything.

## 2. Work packages, in order

All eight are done. Rule #0.5 held throughout — **no file over 250 lines, no method
over 50** — and the splits below are chosen with that in mind, not retrofitted.

### WP0 — Staff (`lib/staff/`) — ✅ done

**Added mid-stage (user, 2026-08-30): the product had no operator concept at all.** Beta enrolment
is RocketEase's decision, and without staff the only way to make it — or to support a customer, or
investigate an incident — was hand-written SQL against production, unaudited.

- `db/schema/staff.ts` — `staff_user`: `user_id` (PK), `role` (`support` | `admin`),
  `granted_by_user_id`, `note`, timestamps.
- `lib/staff/policy.ts` — pure: `parseStaffEmails`, `resolveStaffRole`, `staffAtLeast`.
- `lib/staff/index.ts` — `staffRole()` (React-cached), `requireStaff(minimum)`, `setStaffRole`,
  `storedAdminCount`.
- `lib/staff/queries.ts` — `listStaffOrganizations()`: metadata only.
- `lib/actions/staff.ts` — `grantBeta`, `revokeBeta` (admin), `listGrants` (support).
- `app/staff/page.tsx` + `components/staff/beta-control.tsx`.

**The invariant that keeps tenancy intact:** staff is a property of a PERSON and is orthogonal to
tenancy. It is never a workspace or organization role, `requireStaff` never composes with
`requireWorkspace`, and `/staff` lives outside `/app/:workspaceId`. There is deliberately **no code
path where being staff changes what a tenant-scoped query returns** — which is why v1 reads no
customer content and offers no impersonation.

Other decisions worth keeping:

- A non-staff visitor gets **404, not 403** — the surface does not advertise itself, the same reason
  `requireWorkspace` redirects rather than leaking that a workspace exists. Denials by an
  authenticated user are audited; anonymous scanners are not.
- `STAFF_EMAILS` bootstrap requires a **verified** email, and matches whole addresses, never
  substrings. A stored row always wins, so a bootstrap address can be demoted without a redeploy.
- Staff actions are audited against the **target organization**, so a customer sees in their own
  audit trail that we acted on their account.
- Better Auth's `admin` plugin was not used: it would mean regenerating `db/schema/auth.ts` (a
  documented dance) and coupling to plugin semantics, for impersonation and banning we do not want
  in v1. Revisit if impersonation is ever needed — with a consent and audit design first.

### WP1 — Beta gate (`lib/features/`) — ✅ done

- `db/schema/features.ts` — `feature_grant`, unique on `(organization_id, feature)`, with
  `expires_at` for time-boxed pilots.
- `lib/features/policy.ts` — pure: `BETA_FEATURES`, `decideAccess`, `parseBetaEnv`. Precedence: a
  stored row wins (an explicit revoke beats the env bootstrap), then `BETA_FEATURES`, then closed.
- `lib/features/index.ts` — `hasFeature`, `featureAccess`, `isInvited`, `describeGrants`. **No
  `server-only` import**: the worker checks grants too.
- `lib/actions/features.ts` — `setBetaParticipation`: an org may leave a beta and rejoin one it was
  invited to, but **cannot grant itself one**.
- Migration `0017_clean_silver_fox.sql`, applied. 26 unit tests; full suite 481 green.

### WP2 — `packages/media` + mock adapter — ✅ done

New source-only workspace package, wired into both Dockerfiles, `transpilePackages`, and the platform's
dependencies.

- `src/types.ts` — `JobKind` (14 kinds), `GenerationSpec`, `MediaJobState`, `RawOutput`, `CostEstimate`,
  and `MediaError` carrying the same `category`/`retryable`/`ambiguous` triple as `ProviderError`.
- `src/io.ts` — `ModelIO`: inputs accepted, outputs produced, duration rules, audio disposition,
  delivery mode and **URL TTL**. Plus `supportsDuration`, `nearestDuration`, `referenceCapacity`,
  `isStale`.
- `src/catalog.ts` — the registry. `modelByKey` resolves retired models on purpose, so a historic
  `media_job` still reads back.
- `src/routing.ts` — `JobKind` → ordered candidates, every decision carrying a `model_reason`.
  Fallback happens only **before** any spend.
- `src/cost.ts` — `estimate()` returns `{ unknown: reason }` rather than a guess; `parseRates` mirrors
  `AI_PRICES_JSON` and ignores malformed values rather than reading them as zero.
- `src/adapter.ts` — the `MediaAdapter` interface. `reconcile()` is **not optional**.
- `src/mock/` — a first-class adapter with **real decodable media** (1s H.264 MP4, 1s MP3, 1×1 PNG),
  a genuine async shape (running for two polls), a URL TTL, and reconcile-by-idempotency-key.

58 tests. The mock deliberately carries awkward shapes real vendors have — fixed durations only
(`4 | 8`, like Sora's `16 | 20`), URL delivery with an expiry, and a claimed duration a fraction off
the file — so those paths are met locally rather than in production.

### WP3 — Schema + migration `0018` — ✅ done

- `db/schema/media.ts` — `media_job`, unique on `(workspace_id, idempotency_key)`, with
  `model_reason`, `spec`, `seed`, `quantity`/`unit`, nullable `vendor_cost_usd`, `mismatches`, and a
  `(state, updated_at)` index for the poller.
- `db/schema/assets.ts` — `ASSET_KINDS` += `audio`; `RENDITION_KINDS` += `captions`, `waveform`; plus
  `media_job_id`, `derived_from_asset_id`, `provenance`, `license_source`, `platform_clearance`.

The `ALTER TYPE ... ADD VALUE` the plan warned about applied cleanly on PG 17 — nothing in the same
migration uses the new value. The enum change also made the compiler find both places that needed
`audio` (`components/library/types.ts`, `lib/actions/assets.ts`), which is the whole reason to widen a
union rather than a string.

### WP4 — ffprobe toolchain — ✅ done

- `lib/media/ffmpeg.ts` — one spawn wrapper, wall-clock timeout, bounded stderr, and one place that
  decides a tool is missing. `MediaToolError.missing` is what callers treat as unknown.
- `lib/media/probe-parse.ts` — pure parsing. ffprobe reports stringly numbers, durations on either
  the format or a stream, and frame rates as fractions; each is parsed explicitly and anything
  unreadable becomes **null, never 0**.
- `lib/media/probe.ts` — `probeBuffer`, `posterFrame`.
- `lib/media/sniff.ts` — container from bytes, generalising the sniff already in `images.ts`.

40 tests, including integration tests that generate real media with ffmpeg and probe it. They skip
cleanly when ffmpeg is absent.

### WP5 — `asset.process` split and extended — ✅ done

Split before extending, as planned: `worker/handlers/asset/{image,video,audio,scan,renditions}.ts`
with the handler as orchestration only (66 lines).

**The defect is closed.** A video upload now learns its real duration and dimensions and gets a
poster frame plus a thumb. `Capabilities.limits.videoMaxSeconds` finally has something to validate
against — the wiring in `lib/content.ts` was always correct, it was just being handed `null`.

The second half of that bug is also fixed, in `packages/providers/src/validate.ts`: an **unknown**
duration used to pass silently. It now raises a warning naming the limit that could not be checked,
and `video_too_long` names the actual length.

### WP6 — Queues, worker roles, media deployment — ✅ done

- `media.generate` — `stately`, `retryLimit: 0`. `media.poll` — `singleton`, tight backoff.
- **`asset.process` moved to the media role**: it runs ffmpeg now, so it belongs to the worker with
  the CPU and the scratch disk. That was not in the original plan and is the right call.
- `role` lives in the queue registry, not a `WORKER_QUEUES` env list — a test asserts every queue is
  owned by exactly one role, so a new queue cannot be silently dropped by both processes.
- `worker/schedules.ts` — the general worker's timers, extracted so the role split is a one-line
  branch rather than a giant `if`. `worker/index.ts` is down to 73 lines.
- `Dockerfile.worker` installs ffmpeg; `deploy/k8s/base/media-worker.yaml` runs the same image with
  `WORKER_ROLE=media`, 2 CPU / 4Gi, and a 20Gi `emptyDir` scratch volume. Added to the production
  overlay's **env-hash patch** (without it a rotated secret would reach the cluster and never be
  read — the trap that bit this repo on 2026-08-29) and to CI's rollout wait.

### WP7 — Normalization and the generation loop — ✅ done

- `lib/media/normalize.ts` — pull bytes, sniff, probe, record mismatches, then the normal door:
  storage → `asset` → `asset.process`.
- `lib/media/ceiling-policy.ts` (pure) + `ceiling.ts` (env + ledger) — blast-radius limits checked
  **before** any adapter call. An unpriceable job with a per-job ceiling configured is refused, not
  waved through: "we don't know what this costs" is the worst reason to spend.
- `lib/media/jobs.ts` — route → estimate → ceiling → row + outbox emit, in that order, so a refusal
  costs nothing and leaves no half-state.
- `worker/handlers/media-generate.ts` — **reconciles before starting**. If an earlier attempt reached
  the vendor and we lost the answer, starting again bills twice.
- `worker/handlers/media-poll.ts` — fetches the moment a job completes, because the URL TTL is a
  deadline. A poll *error* never fails a job; the vendor may still be working.

### WP8 — Minimal surface — ✅ done

`lib/actions/media.ts`: `previewGeneration` (model, reason, and cost — or an honest "unknown") and
`generateMedia`. Both check `hasFeature` **server-side**.

## 5. Dogfood corpus

Seven live brands are available to test against, which is a materially better corpus than one:

`sparx.works` · `meetpiggles.com` · `jotacular.com` · `silicaui.com` · `wize.works` ·
`agconn.com` · `kanninja.com`

Set each up as a workspace with a real brand kit (M10) before 12.2 — the kit is the input the whole
reference-conditioning design depends on, and building it for seven different brands is itself a
test of whether the kit model holds.

**Watch for the cluster.** Most of these are B2B software; that is not the same as category spread.
Product photography, physical goods and regulated verticals will exercise the fidelity and
compliance paths that a dev-tool brand never touches. Worth an external design partner before any
routing default in `docs/media-models.md` §3 is treated as settled.

Private posting to a real network is required for Meta's review anyway, so the provider work (owned
by another agent) and this stage feed each other rather than competing.

## 6. What 12.1 turned up

Resolved along the way:

1. **The product had no operator concept** — see WP0. Bigger than beta grants: without it, enrolling
   anyone or supporting a customer meant unaudited SQL against production.
2. **`asset.process` belongs to the media worker**, not the general one. It runs ffmpeg now.
3. **A mock must emit real media.** The first fixtures were hand-rolled MP4 box stubs; ffprobe could
   not read them, so local dev never exercised the probe or poster path — the exact code this stage
   adds. Replaced with a real 1s H.264 MP4 and a real MP3.
4. **A mock must not lie about its own output.** The fixtures initially claimed 1280×720 while
   delivering 32×32, so every job reported a mismatch. A mock that cries wolf trains people to ignore
   the signal; claims now describe the file.

Still open, and cheap to answer once there is real usage:

1. **Transcode ladder** — probably per-network at publish time rather than eagerly on upload.
   Measure storage before deciding.
2. **Scratch volume sizing** — 20Gi is a guess. Find out with a real 4K render.
3. **Poster frame timestamp** — 10% in is wrong for a clip that opens on black. Revisit when hooks
   matter (12.4).
4. **`media_job` retention** — these rows carry the cost history the pricing decision depends on.
   Confirm they are out of scope for the standard retention sweep.
5. **Waveform renditions** — declared in `RENDITION_KINDS`, not yet generated. Lands with 12.3, where
   there is a player to draw them under.
