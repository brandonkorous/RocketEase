# M12.2 — Static ad creative

**Status:** ✅ done 2026-08-30 · **Depends on:** M12.1 (pipeline foundation) · **Unblocks:** 12.3–12.5

The stage where the *quality* argument gets built. 12.1 proved we can spend money at a vendor
safely; 12.2 is the part that makes the output worth buying — brand-bound references, deterministic
type, and a placement preflight that says why something will not work before it ships.

Static first is deliberate. Every mechanism here — the reference set, the compositor, the safe-zone
geometry, the variant discipline, the preflight — is reused wholesale by video in 12.4, and it gets
proven at cents per attempt instead of dollars (`docs/media-generation.md` §10).

---

## 1. What "done" means

A person with the beta grant can build an **editable plan** rather than a picture, render it to one
file per placement, and be told — deterministically, with a reason — if the CTA sits under the Reels
UI, if the source is too small for the canvas, if the rights clock on the packshot expires before
the flight ends, or if the brand's font could not be confirmed and something else may have been
substituted.

Nothing here invents copy. Nothing here diffuses a price.

---

## 2. The three rules this stage exists to enforce

1. **Composite type, never diffuse it** (`docs/media-models.md` §6). The offer, price, CTA, logo and
   legal line are drawn from the brand kit with real strings, real hex, real fonts. A model that
   spells `$49.99` right 95% of the time publishes a wrong price one time in twenty.
2. **The product is a reference, not a description.** A real packshot conditions the generation; the
   model never invents the label. When the routed model cannot take every reference, the ones it
   drops are *named on the job*, never silently discarded.
3. **Placement is geometry, and geometry is checkable.** Meta's unified safe zone (14% top / 35%
   bottom / 6% sides, March 2026) is a number. If we own the overlay we own the placement, so the
   preflight can assert it rather than hope.

## 4. Design decisions taken here

**`AdPlan` rides on `content_item.ad_plan`**, per `docs/media-generation.md` §5, and the column is
deliberately untyped in the schema: it can hold a plan written by an older build, so every read goes
through `plan/schema.ts` rather than trusting the shape.

**Renders are recorded on the plan**, each stamped with the fingerprint that produced it. The
fingerprint is taken over the fully *resolved* render spec — copy, resolved hex, pixel geometry,
source asset — so renaming a plan invalidates nothing and changing the brand's primary swatch
invalidates everything that used it. "This render is out of date" becomes a comparison.

**Text is measured, not estimated.** sharp's Pango text input does real line breaking and reports
the size it produced; layout consumes that. Estimating glyph advance would misplace every overlay in
a font we do not have — exactly the case we most need to be right about.

**The renderer reports; the preflight judges.** `renderAd` returns where each overlay landed, which
fonts it got and whether it had to upscale. A renderer that also decided what was acceptable could
never be checked.

**Dimensions block, safe zones warn.** Meta publishes its canvas sizes; nobody publishes the
14/35/6 safe zone in a form we could read. So a safe-zone collision warns and the message carries
its own provenance, rather than blocking a customer's ad on somebody else's blog post.

## 5. Explicitly out of scope

- Video assembly, captions, audio (12.3/12.4).
- Real vendor image adapters (fal/OpenAI). The mock adapter proves the loop; wiring `fal` is a
  credential decision, not a code decision, and the registry already carries the models.
- A designed screen. `images/` has no ad-composer mockup, and screens follow the mockups. The engine
  and server actions ship here; the surface lands when there is a design to build to.

## 6. What the build actually found

**The brand kit stores logos by STORAGE KEY, not asset id.** Modelling both as "an id" would have
produced a logo key silently failing an asset lookup. `lib/media/locator.ts` puts the difference in
the type, so the two cannot be confused again.

**Two different `ReferenceRole` types wanted to exist.** `@rocketease/media`'s names the input slot a
model exposes (`subject`, `style`, `ingredient`…); ours names what the reference *depicts*. Ours is
now `ReferenceKind` — two identically-named types meaning different things is a bug waiting for a
careless import.

**A derived asset must inherit its source's rights envelope.** Otherwise "render it" is a one-click
way to launder an asset out of its own licence. Licence expiry, organic-vs-paid scope and
per-network clearance all carry over in `render-store.ts`.

**Generic font families are not reliably distinct from the fallback.** The substitution probe renders
a sample in the requested family and in a family that cannot exist, and compares metrics — portable,
no `fc-list` needed, and it measures the thing we care about. But on a box without fontconfig
generics, `sans`, `serif` and `monospace` all measure identically to the impossible family, so a test
asserting "monospace resolves" is environment-dependent rather than a fact. It discriminates real
named families correctly, which is the case that matters. The worker image now installs
`fontconfig font-dejavu font-noto font-inter`; verified in that image, `sans` → Noto Sans and
`Inter` → Inter.

**Fingerprinting the RESOLVED spec pays off immediately.** Editing a headline stales the base
renders but leaves the hook-variant renders current — because that variant overrides the headline
anyway. Nobody designed that; it falls out of hashing what would actually be drawn.

**`lib/brand/store.ts` was `server-only`,** so the worker could not read a brand kit to composite in
its colours. Reads moved to `lib/brand/load.ts`; writes stayed behind `server-only` on purpose.

## 7. Open questions

1. **Where brief → plan lives.** `lib/ai/generator/` already owns brief → concept. An ad plan is the
   same shape one level up. Reuse or fork?
2. **Logo role selection.** The kit has 8 logo roles. Choosing `mono_light` vs `primary` from the
   background's mean luminance is a small, honest heuristic — or a person's choice. Currently a
   person's choice; `starterPlan` only suggests.
3. **Font delivery.** Brand fonts are licensed. Uploading a foundry font into a render container is a
   licensing question we should not answer on the customer's behalf.
4. **Orphaned renders.** `orphanedRenders()` finds files left behind by a plan edit, but nothing
   deletes them yet — a previous render may already be attached to a published post.
