# M12.4 — Video assembly

**Status:** ✅ done 2026-08-30 · **Depends on:** M12.1–12.3 · **Unblocks:** 12.5

"One brief, five placements" as a real, repeatable flow. Everything 12.2 and 12.3 built for stills
and audio now runs over moving pictures — the same compositor draws the type, the same safe zone
sets the caption margin, the same rights model decides what the cut may be used for.

---

## 1. The finding this stage is built on

**The concat demuxer requires identical streams**, and shots do not arrive identical. Different
models return different resolutions, frame rates, pixel formats, and some return no audio track at
all. Concatenating them as they come produces a file that plays for two seconds and then stops —
with no error anywhere, from ffmpeg or from us.

So assembly is deliberately **two passes**: every shot is first normalised to the same canvas, fps,
pixel format and audio layout, and only then joined. It costs disk, which is what the media worker's
scratch volume is for.

## 3. Decisions taken here

**The picture decides the length.** `amix=duration=longest` will happily run audio past the last
frame, producing a container longer than the video and a dead tail on every player. `-shortest` fixes
it — and when the voice-over is what got cut, the job says so, because somebody wrote that script.

**The audio graph is built as text and tested as text.** An ffmpeg filter chain is exactly the kind
of thing that is wrong in a way you only discover four minutes into a render.

**`amix` normalisation is turned OFF.** Its default halves every input's level, which quietly makes
a mixed track much quieter than a lone one — the sort of bug that gets blamed on the source material.

**Ducking is keyed on the voice, with the key padded.** `sidechaincompress` stalls if the key stream
ends before the bed does. Without ducking people do not turn the music down; they turn the video off.

**Rights merge on four independent axes.** Scope, expiry, licence source and per-network clearance do
not travel together: the organic-only restriction can live on one clip while the earliest expiry
lives on another and the TikTok block lives on the music. Inheriting from a single "base" asset gets
three of the four wrong. `mergeRights` takes the narrowest of each, and the job reports what it
narrowed.

## 4. What the build found

**`10 ** (db / 20).toFixed(6)` applies `toFixed` to the EXPONENT.** The test passed anyway because
JavaScript coerced the string back to a number; only the typechecker caught it. The rounding it was
supposed to do never happened.

**The end-to-end smoke produced a 4.1s file from a 3.4s cut** — the voice-over was extending the
container. That is the `-shortest` finding above, and it now has a regression test asserting the
output duration follows the picture.

**Overlay rendering wanted to share the compositor's whole middle.** `renderAd` and
`renderOverlayLayer` now both call one `renderOnto`, so measurement, layout and painting cannot
diverge between a still and a video.

## 5. Verified end to end

Three clips at 1280×720@25, 1080×1920@24 and 640×640@30, plus a voice-over with captions, assembled
into a single 1080×1920@30 cut with audio. The merged rights came out `organic` / `stock` /
`tiktok: false` / expiring 2026-12-01 — each restriction inherited from a different ingredient — and
the notes explained every one of them.

## 6. Explicitly out of scope

- Music generation and `platform_clearance` for generated beds (12.5).
- C2PA re-signing (12.5) — it needs a certificate in Key Vault, set by hand.
- Transitions, speed ramps, smart reframe. The cut is hard cuts, which is what a 6-second ad wants.
- A timeline editor screen. `images/` has no mockup for one.

## 7. Open questions

1. **Where the captions for an assembly come from.** Currently the voice-over's own caption track,
   which is right when there is a voice-over and silent when there is not. A cut whose speech is in
   the source clips has no captions at all yet.
2. **Loudness on a silent cut.** `loudnorm` is skipped when there is no audio, which is correct, but
   the resulting file has no audio stream at all — some networks prefer a silent track to none.
3. **Segment caching.** Every re-render re-normalises every shot. Shots rarely change; the overlay
   almost always does. Caching normalised segments by (asset, trim, canvas) would make copy edits
   nearly free, the way they already are for stills.
