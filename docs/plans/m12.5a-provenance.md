# M12.5a — Content credentials: probe, record, disclose

**Status:** ✅ done 2026-08-30 · **Depends on:** M12.1–12.4, 12.4a · **Unblocks:** 12.5b (re-signing)

The provenance half of 12.5. The motion half (reference-conditioned `product_motion`, `sequence`,
`footage_edit`, `performance`, music) is untouched and blocked — see §6.

---

## 1. The finding this stage is built on

**We were asserting a credential we had never looked for.** `ModelDescriptor.provenance.c2pa` is the
vendor's claim about their product; the pipeline wrote it straight onto the asset as fact, and the
whole "was it stripped" chain was built on top of that assumption. A file the vendor signs but we
mislabel `absent` loses the record that a credential existed at all — and a file we mark `signed`
without checking is a lie to a customer about their own disclosure.

This is the same rule ffprobe already enforces for duration: **probe, never believe.** The claim is
now checked against the bytes, and a disagreement is recorded in `media_job.mismatches` next to
"claimed 8s, delivered 7.4s".

The deadline is not hypothetical. **EU AI Act Art. 50 — machine-readable marking of synthetic
content — has applied since 2 Aug 2026**, and TikTok and Meta auto-label from the credential. A
pipeline that re-encodes AI video silently is *removing* the disclosure the model vendor attached.

## 3. Decisions taken here

**Detection, never validation.** Nothing here says "verified". Validating a signature needs the C2PA
trust list and is a different job; claiming validation we do not perform would be the exact failure
this stage exists to prevent.

**Container-independent detection.** A C2PA manifest store is a JUMBF superbox (ISO/IEC 19566-5):
`jumb`, then a `jumd` description box labelled `c2pa`. Requiring all three in sequence beats
per-container magic numbers — it is one code path for PNG, JPEG, MP4 and WebP, and it does not rest
on constants nobody here has read off a spec page.

**Precision over recall, deliberately.** Missing a credential under-claims (we say `absent` about a
signed file). Inventing one lies to a customer. So the scan is bounded — 8MB head, 2MB tail — and
`bounded: true` is reported so `absent` is never overstated as proof.

**Warnings, not blocks.** A caption disclosure is a real disclosure, and re-signing does not exist
yet. Blocking every AI render on a missing credential would make the feature unusable and would not
make anybody more compliant.

**`stripped` is worded as something that happened.** It is the one we caused, and the only one
re-signing can fix. `absent` is a fact about the vendor; `stripped` is a fact about us.

## 4. What the build found

**A stripped credential is not only an AI problem.** Cameras sign too. `credentialIssue` reports a
`stripped` state on an ordinary photograph as well, because our pipeline removing a photographer's
credential is the same harm with a different owner.

**The offset in `CredentialScan.at` is the `jumb` marker, four bytes into the box.** Reporting the
box start would need an `i - 4` that can underflow; the marker offset is unambiguous and is only
ever an audit-trail value.

## 5. Verified

15 tests on the detector against constructed JUMBF fixtures — a real manifest, a JUMBF box that is
not C2PA, the word `jumb` on its own, a manifest at the end of a >10MB file, and one hidden in the
skipped middle (which must report `absent` *and* `bounded`). 7 on the disclosure rule.

## 6. Explicitly out of scope — and why

**Re-signing (12.5b) is blocked on a certificate**, set by hand in Key Vault under the same rule and
for the same reason as `TOKEN_MASTER_KEY`. No stub was written: an unimplemented `signCredential`
that always errors is dead code pretending to be a seam. What exists instead is an accurate record
of every strip, which is what re-signing will consume when the certificate lands.

**Advanced motion is blocked on vendor credentials.** `product_motion` (Seedance), `sequence`
(Kling), `footage_edit` (Aleph) and `performance` (Act-Two) each need real API access before a
descriptor can be written, because a descriptor is a set of claims read off a vendor's page by a
person — not something to be guessed from a comparison table.

**Music generation is blocked on a vendor decision.** The licensed-training-data question is the
whole point of the choice (research §11), and it is not ours to make unilaterally.

## 7. Open questions

1. **No UI surfaces provenance.** The publish-time warning is where the decision is made, so that is
   the surface that matters — but the media library shows nothing about a file's credential state,
   and there is no mockup for one.
2. **Watermarks are recorded but never probed.** `provenance.watermark` still comes from the
   descriptor. SynthID is not detectable without Google's detector, so the claim is all we have —
   which is worth stating rather than quietly treating as equivalent to the C2PA field beside it.
3. **A bounded scan on a very large video.** 8MB head + 2MB tail covers where manifests actually
   live, but a 500MB render with a manifest in the middle reports `absent`. It is recorded as
   bounded; nothing yet acts on that distinction.
