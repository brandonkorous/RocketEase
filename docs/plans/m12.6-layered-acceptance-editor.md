**WP6 — Orchestrated length (user decision, 2026-09-01).** The platform is an orchestrator,
not a fal passthrough: a person picks a REAL content length (15/20/30s), and
`lib/media/plan/duration.ts` splits it into model-legal takes that sum exactly to the

whole piece.

**Also decided 2026-09-01: no quick video tool.** The library's one-click clip generator
was removed (`generate-video-panel.tsx`, `lib/actions/video.ts`) — a "quick" button on
the most expensive thing in the product is a cost trap for us and the client. The rail
points at the plan flow instead; the voice-over chain it introduced stays
(`lib/media/voiceover-chain.test.ts` pins it) because plan shots use it next.

**Next (WP7, not started): take chaining for continuity.** Independent takes cut hard.
Kling I2V accepts a start image, so take N+1 can open on take N's LAST FRAME:
`asset.process` gains a `last_frame` rendition for generated video, and a shot gets
`continueFromPrevious` — when set, the previous shot's last frame rides as the reference.
Needs the rendition first; nothing else blocks it.

Decided with the user 2026-09-01, from the competitor research
(`docs/research/generation-competitors-2026.md`): keep audio, video, graphics and captions on
separate layers until a person accepts the output, and give them an editor over those layers.

## 1. The finding this stage is built on

**Every rival flattens early, so every edit re-bills.** Runway, OpenArt, DaVinci and Creatify all
hand back a finished MP4; changing a caption or a price costs credits again (Creatify literally
bills revisions), and charging for edits and failed takes is the top complaint on all four
Trustpilot pages (research doc §6).

Our pipeline already keeps the ingredients apart — `AdPlan` is a plan, not pixels; type and logo
are composited; caption cues derive from words on every read; the audio graph is built per render.
The gap is purely product surface: **assembly flattens before the person ever sees the work.** The
principle this stage installs:

> **A render is a preview until a person accepts it. Layers stay live until acceptance, and an
> edit to any layer we own costs $0.**

### The layer model

| Layer | Source | Edit cost |
|---|---|---|
| Shots (generated or uploaded footage) | vendor pixels — **baked** | regenerate = the only paid edit |
| Voice-over | `voice` + script → TTS | re-TTS = cheap spend, priced first |
| Music bed / SFX | asset + volume/ducking settings | $0 |
| Captions | `caption_track` words → cues derived | $0 |
| Type, logo, legal line | composited from the brand kit | $0 |

One boundary, stated honestly in the UI: pixels *inside* a generated shot are baked. Layering
covers everything we add on top — which is everything legally sensitive.

## 3. Decisions taken here

**A plan editor, not an NLE.** The research doc names the generic editing canvas as a phase-2 trap
(large UI build, OpenArt/Runway's turf). The editor edits the `AdPlan` and its tracks — the layer
document that already exists — never a freeform timeline.

**The browser preview approximates; the render is authoritative.** Ducking and loudness in
WebAudio will not match the ffmpeg mix exactly. Divergences are reported (the 12.2 font-report
idiom), never hidden. A "render proxy preview" server pass stays available behind a button if the
approximation proves misleading.

**Edits never bill; only generation does.** This is policy, made checkable: the $0-spend gate in
WP2 is a test, not a hope. It is also the marketing line the research doc recommends, because no
rival can copy it without cutting revenue.

**Image routing (recorded from the same discussion).** The default image model **stays
`azure-gpt-image-2`** — measured $0.0154/image, GA on Azure to 2027-10-21, in-cloud. fal is added
for *breadth, quota and per-job fit*, not price: Flux for `product_still`, Ideogram/Recraft for
text-inside-image, Schnell-class for cheap `scene_still`. Registry rows, not a migration.

**Prerequisite tracked elsewhere:** `azure-sora-2` retires 2026-10-15 (verified; research doc §0).
The replacement video route (fal/Kling default, Vertex/Veo premium) lands under 12.5b's adapter
work and is not blocked by — and does not block — this stage.

## 4. Open decisions

1. **Where acceptance lives** — on `content_item.ad_plan` as a whole, or per placement (a 9:16
   accepted while the 1:1 is still being tweaked). Leaning per-placement, since renders and
   preflight are already per-placement.
2. **Overlay positioning freedom** — safe-zone anchor presets only (12.2's current shape) vs free
   drag clamped to the safe zone. Leaning anchors first; free drag only if dogfooding demands it.
3. **Preview of multi-shot sequences** — sequential `<video>` playback per shot vs one normalized
   proxy render for scrubbing. Leaning sequential first; proxy behind a button.
