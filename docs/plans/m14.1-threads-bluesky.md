# M14.1 — Threads and Bluesky adapters

**Status:** built and unit-tested against stubbed HTTP, 2026-09-05. The Bluesky connect flow was
driven live on the dev server (`apps/platform/e2e/.state/bluesky-live/run.ts`, git-ignored): the
public capabilities page lists both networks, Connect account offers Bluesky, a main-password-shaped
secret is refused before any network call, and a well-formed wrong app password gets Bluesky’s own
401 back as a plain message while the handle survives the form reset. No real account was
connected: Threads needs the app secret copied into `.env`, Bluesky needs one app password. Both
are free and need no review, so they are the first networks that can be dogfooded live.

Found on the way: `err instanceof ProviderError` is false in Next’s dev server when the adapter
registry (cached on `globalThis`) was built by another compiled copy of the package, so the new
action uses `isProviderError()` (name-based). The older OAuth paths still use `instanceof`; they
are fine in a production build and worth switching when next touched.

## What each one is

| | Threads | Bluesky |
|---|---|---|
| Vendor | Meta, but a **separate app id** from the Meta app (`docs/provider-apps.md`) | AT Protocol; no developer console at all |
| Sign-in | OAuth at `threads.net/oauth/authorize`; 1-hour token swapped for a 60-day one; refreshed with `th_refresh_token` once it is 24 h old | **App password** (`xxxx-xxxx-xxxx-xxxx`) against `bsky.social`; the platform renders the adapter's `credentialsForm` and calls `signIn`. A main password is refused by shape before it leaves the form |
| Publish | container → `threads_publish`; TEXT, IMAGE, VIDEO, CAROUSEL (2–20 items); media containers polled until `FINISHED` | one `createRecord` of `app.bsky.feed.post`; one embed per post (≤4 images, or one MP4, or a link card) |
| Idempotency | none in the API; the attempt is remembered in-process and reconciled by text + time over the profile's recent posts | the record key is a TID derived from the idempotency key, so the same key can never create a second post and reconciliation is a `getRecord` |
| Limits (sourced) | 500 characters; images ≤8 MB JPEG/PNG; video ≤1 GB, ≤300 s; **250 posts + 1,000 replies per 24 h** | **300 graphemes**, 3,000 bytes; images ≤1,000,000 bytes; video ≤300 MB MP4, ~3 min; writes 5,000 points/h, 35,000/day (a post is 3) |
| Inbox | replies on recent posts (`/{media}/conversation`); reply = container with `reply_to_id`. Mentions need webhooks with Advanced Access → declared off with the reason | `listNotifications` (reply → comment; mention, quote → mention); reply = post with `root`/`parent` refs. DMs need a chat-scoped app password and a second service → declared off |
| Insights | per-post `views, likes, replies, reposts, quotes, shares` (lifetime); daily `views` series; `followers_count` | `getPosts` counts (likes, replies, reposts + quotes); `followersCount`. **No views or impressions exist** |
| Not there, said so | AI-disclosure field, cover frame, ads, webhooks (until Advanced Access), first comment, DMs, reviews | AI-disclosure field, cover frame, ads, webhooks (the firehose is not per-account), first comment, reviews, audience demographics |

## Contract change

`ProviderAdapter` gained `credentialsForm?` and `signIn?(values)` for networks without OAuth.
The start route sends such an adapter to `/app/:ws/accounts/connect/:provider`, a form built from
the adapter's own field list; the action `signInWithCredentials` verifies with the network, seals
the credential exactly like an OAuth token (`persistConnection`, shared with the callback route),
audits `connection.start` / `connection.authorized` / `connection.failed`, and lands on the same
channel-selection step every other network uses.

## Where the numbers came from

- Threads: developers.facebook.com/docs/threads — `posts` (limits, container flow, 250/24 h),
  `overview` (1,000 replies/24 h, `threads_publishing_limit`), `get-started/long-lived-tokens`,
  `threads-profiles`, `insights`, `reply-management`, `webhooks`. Read 2026-09-05.
- Bluesky: the lexicons in `bluesky-social/atproto` (`app.bsky.feed.post`, `embed.images`,
  `embed.video`, `video.defs`, `notification.listNotifications`) and
  `bluesky-social/bsky-docs` (`advanced-guides/rate-limits`, `advanced-guides/posts`). The
  three-minute video duration is Bluesky's 2025 announcement, not a lexicon; the video service is
  the judge and its failure is reported.

## Deferred

- Threads webhooks (`replies`, `mentions`): same signature scheme as Meta's; wire when the app has
  Advanced Access and a verified business.
- Threads `manage_reply?hide=true` — for M14.6 (moderation).
- Bluesky DMs (`chat.bsky.convo.*` via the `atproto-proxy` header) and AT Protocol OAuth (needs a
  hosted `client_metadata.json` and DPoP).
- Grid surfaces: neither network renders a profile grid, so none was added.
