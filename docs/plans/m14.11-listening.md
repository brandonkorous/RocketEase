## What it is

Two things on one screen under Analytics (`/analytics/listening`), so the sidebar stays at ten items:

- **Listening** — saved keyword queries (name, terms, networks) checked every 30 minutes on the networks
  that let a third-party app search public posts; a paged feed of hits; a coverage strip that says, per
  network, what is searched and why the rest are not.
- **Ad library** — a live search of the public ad repositories the EU's Digital Services Act requires
  (Meta Ad Library, TikTok Commercial Content Library) by term and country; results are the source's own
  figures and nothing is stored.

## Decisions

- **Only what a network lets an app search is searched.** `LISTENING_COVERAGE` (`lib/listening/coverage.ts`)
  carries the words and the document for every yes and the reason for every no; the screen shows them,
  and the query dialog says per network how it is reached in THIS workspace (Bluesky: the connected
  Bluesky account; Threads: the connected profile, reconnect if the keyword-search permission is
  missing — it is now in the default Threads scopes; YouTube: the connected channel).
- **Every search runs as a connected account** (`searchAs`, `lib/listening/credentials.ts`). The first
  draft said Bluesky needed none; the live run proved otherwise (403 above), so the claim was removed
  rather than worked around. A Bluesky session token is short-lived; `loadCredential` refreshes it the
  way publishing does.
- **A hit has a definition.** One public post that matched one of the query's terms at check time; a later
  edit or deletion at the network is not seen. Unique per (query, network, post), so a post is captured
  once; "Hide from feed" keeps the row so it is not captured again.
- **Every check is recorded per network** (`listening_check`: ok / failed with the network's words), so
  the query card can say "checked 12 min ago" and "⚠ Threads: reconnect …" honestly. A failed network never
  stops the others. The first check reaches 7 days back; later ones re-read a 10-minute overlap.
- **Listening is not the inbox.** Mentions of the workspace's own accounts stay in the inbox; the screen
  says so.
- **The ad library stores nothing.** Every search asks the source again; dates and reach are the
  repository's own figures, labelled as such. Meta is read with the connected Facebook Page's user token;
  TikTok needs the application approved (`TIKTOK_COMMERCIAL_CONTENT=1`), and says so until then.
- **Paging, not load-more**, on the feed (numbered pages) and the ad results (Previous / Next over the
  sources' cursors).

## Launch chores (yours)

- Threads: connections made before today lack `threads_keyword_search`; reconnect to grant it (the screen
  says so per workspace).
- TikTok: apply for the Commercial Content API at developers.tiktok.com; set `TIKTOK_COMMERCIAL_CONTENT=1`
  when approved.
- Meta: the Ad Library is read with the connected Facebook login, which must have confirmed its identity
  with Meta; otherwise Meta's refusal shows in its words.

## Left out on purpose

- X search: metered per read; needs a plan decision before it is switched on.
- Reddit: commercial use needs Reddit's written approval; not requested.
- Instagram hashtag search (30 a week): a later step, with its own definition.
- Sentiment, alerts and digests on hits: the feed first; rules can come through Settings › Automations
  later with a `listening.hit` trigger.
