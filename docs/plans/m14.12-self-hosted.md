## What it is

RocketEase running on an agency's own cluster under a licence key (challengers.md whitespace #6:
"self-hostable / licence-owned agency tier"). Five things, in the order the plan row lists them:

| Piece | What it means here |
|---|---|
| **Single-org mode** | `DEPLOYMENT_MODE=self-hosted`. The install has ONE organization: the first person to sign up claims it. After that an account is created only for an address holding a pending workspace invitation; everyone else is told whose install it is, on the sign-up form and in onboarding. Enforced in a Better Auth **database** hook (`lib/self-hosted/signup-hook.ts`), so social sign-in and One Tap obey the same rule as the password form. |
| **Licence key check** | `LICENCE_KEY` = `RE1.<payload>.<signature>`: a JSON payload (licensee, id, issued/expires, workspaces or unlimited, included features, channel) signed with **Ed25519**. Checked with the PUBLIC key baked into the build (`lib/licence/public-key.ts`; `LICENCE_PUBLIC_KEY` overrides it for local checks only). Signature first, payload second — nothing unsigned is parsed as a licence. Keys are issued with `scripts/licence.ts` on an operator's machine; the private key never enters a repository. |
| **Offline-safe gating** | Nothing calls out. Entitlements come from the licence (`lib/billing/licence-entitlements.ts`), in the same shape Stripe's do, so every gate reads one thing: workspace creation, new scheduling, the billing page, beta features. Reading, editing, replying and already-scheduled publishing are never gated. |
| **Helm chart** | `deploy/helm/rocketease`, derived from `deploy/k8s`: platform, worker, media worker, optional web and Ingress, ConfigMap with a checksum so config changes roll the pods, and `drizzle-kit migrate` as a pre-install/pre-upgrade hook from the worker image of the same tag. The chart never renders a secret value: one operator-made Secret holds them all. `helm lint` and `helm template` pass (helm 3.16.4). |
| **Update channel** | `stable` (tagged releases, `v*` → image tags `vX.Y.Z` and `stable`) or `edge` (every build of main → `edge` and `latest`). The chart's image tag IS the channel unless pinned. `UPDATE_FEED_URL` is empty by default; when set, the general worker reads RocketEase's feed once a day and Settings › Billing says whether a newer build is listed for the channel. The build reports its own `APP_VERSION` and `GIT_SHA` (Docker build args) at `/api/health`. |

## The rules, each with its definition

- **Licensed** — now is before `expiresAt`. Workspaces up to the licence's number (or unlimited);
  the licence's features are granted like an env beta grant (`lib/features`: a stored revoke row
  still wins).
- **Grace** — up to `LICENCE_GRACE_DAYS = 30` after expiry (RocketEase's own rule, in
  `lib/licence/state.ts`). Everything works; a persistent notice names the date.
- **Expired** — after grace: no new workspaces, no new scheduling; everything stays readable and
  exportable, exactly like a lapsed cloud subscription (positioning-2026).
- **Evaluation** (no key) — one workspace; scheduling for `BILLING_TRIAL_DAYS` (default 14, the same
  number a cloud trial uses) from the day the install was claimed; then new scheduling pauses until a
  key is set. An install nobody has claimed yet has nothing to gate.
- **Invalid key** — a key that is set but fails the check is treated as no key, and the billing page
  says WHY in words (malformed / newer format / signature / no public key). The key itself is never
  shown or logged.
- **Up to date** — only when the feed's version label equals the running one. Anything else is
  "a newer build is listed", never a computed distance: an edge build and a stable tag are not
  comparable by number.
- **Staff** — unchanged. `STAFF_EMAILS` in the chart values names the install's operators;
  `/staff` shows the same operational metadata it does in the cloud.

## Decisions

- **The licence is checked, never fetched.** A phone-home would make an offline cluster a broken
  one; a signed key with a baked-in public key answers the same question locally.
- **One Secret, made by the operator.** The chart renders no secret value, so a values file can be
  committed — the same rule `deploy/k8s` follows.
- **Stripe stays off in self-hosted mode** for the platform subscription. Stripe Connect for
  client statements (14.10) is the agency's own account and keeps working.
- **The database hook, not the route hook**, gates sign-up: the rule must hold for every way an
  account can be created.
- **Evaluation reuses the trial length** rather than inventing a second number.

## Launch chores (yours)

- Key ceremony: `pnpm exec tsx scripts/licence.ts keygen`; paste the public half into
  `lib/licence/public-key.ts`; keep the private half in a password manager, never a repo.
- Tag the first release (`git tag v1.0.0 && git push --tags`) so `stable` exists on GHCR.
- Publish the update feed (shape in `lib/updates/feed.ts`) if you want installs to see releases.
- Price the tier; the licence carries what was sold (workspaces, features, expiry).

## Left out on purpose

- White-label (logo, domain, mail identity) — the research names it beside self-hosting; it is its
  own step with its own screens.
- Air-gapped image mirrors and a private registry — documented values (`image.registry`,
  `image.pullSecrets`), not automated.
- Licence revocation before expiry — a short expiry with renewal covers it without a call-out.
