# M14.4 — Brand hub leftovers

**Status:** built and verified live against the dev server, 2026-09-05. No new screen: the header
buttons follow `images/brand-kit.png` ("Export Brand Kit" top right), the copy is a dialog on the
existing Brand page, and the lint surfaces through the composer's existing validation list.

## What it is

Three things M10 left open.

1. **A pre-publish lint that BLOCKS.** Until now the kit's banned words and claim rules only reached
   the drafting model; a person could still type one and schedule it.
2. **Brand-kit export** for clients and freelancers: one self-contained HTML file on the same document
   shell as client reports, and a PDF when the deployment has a Chromium renderer.
3. **Copy a brand from another workspace**, for an agency setting up a sub-brand or a second market.

## Decisions

- **Only what a machine can check without guessing blocks.** `lib/brand/lint.ts` blocks on the
  banned-word list verbatim and on the phrases in quotes inside a claim rule (`No "best in the UK"
  claims` blocks “best in the UK”; the rest of the sentence stays guidance for the model and the
  reviewer). Matching is case-insensitive and whole-phrase — "free" does not flag "freedom" — and
  covers the post text and the first comment. Disclaimers, competitor policy and spelling are not
  linted: nothing defines mechanically when a disclaimer applies, and there is no sourced list of
  spelling variants. The Voice and Rules forms say what blocks and how to quote a phrase.
- **One validation path.** The lint runs inside `validateVariant`, so the composer's live preview,
  scheduling, approval requests, the public API and the publish worker all refuse the same post with
  the same words. `RULESET_VERSION` moved to `2026-09-05.1`. The workspace settings are read once per
  pass and feed both the AI-disclosure rule and the kit.
- **The export is a document, not a page.** `lib/brand/export/` builds a `BrandDocument` (kit, logos as
  data URIs ≤512 KB like the reports, who prepared it) and renders it with the report `DocumentShell`
  plus a few extra classes. Colour appears only in the palette swatches, which are the brand's own
  content. An empty part reads “Not recorded yet”; nothing is inferred. The route
  `/app/:ws/brand/export` (any member) serves HTML; `?format=pdf` renders through the same
  `renderPdf` as reports and answers 503 with a plain sentence when no renderer is configured — never
  a renamed HTML file.
- **Copying moves the kit, not the library.** `lib/brand/copy.ts` turns the source kit into a patch
  per chosen section. Logo files are copied object by object into the target's own storage keys (a
  file storage cannot read is left out and logged). Library asset ids are NOT copied — an asset row
  belongs to one workspace — only external links; the dialog says so. The actor must be a member of
  both workspaces and have `workspace.settings` on the target; the write is audited as
  `workspace.brand` with `copy:<sourceId>` and the section names.
- **Left out on purpose:** the mockup's "Share Brand Kit" (a share link is a public surface that needs
  its own access model, like report shares — a later row) and "Download All Assets" (a zip of library
  media is a media export, not a brand-kit export).
