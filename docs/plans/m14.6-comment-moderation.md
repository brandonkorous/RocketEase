# M14.6 — Comment moderation rules

**Status:** built and verified live against the dev server + worker, 2026-09-06 (see the end of this
file). No new screen: the rules live in Settings › Automations (existing builder) and the results live
in the inbox (existing three-pane screen, `images/conversations.png`), so no mockup was needed.

## What it is

A comment that arrives is tested by the workspace's rules; a rule can **hide** it at the network, **flag**
it for a person, or **draft** a saved reply into the thread. A person can do the same from the thread by
hand. Every outcome is visible on the message, every step is a `conversation_event`, and every change a
person makes is audited.

## Decisions

- **One rules engine.** Moderation is the `inbox.message_received` trigger of Settings › Automations with
  more facts and three more actions — not a second builder. The inbox header links to it ("Moderation
  rules"). A moderation rule acts with its creator's permissions like every other rule
  (`conversations.handle`), and needs no approval gate: nothing it does speaks to a customer on its own.
- **A hide is a request the network may not be able to grant.** `packages/providers/src/moderation.ts`
  (`HIDE_SUPPORT`) records, per network, the document behind the hide endpoint or the reason there is
  none. `hideDecision` (`lib/engagement/moderation/support.ts`) is the one place that answers "can this
  comment be hidden?" — network, kind, the channel's granted permission, the adapter, the connection —
  and the rule action and the Hide button both read it. A hide the network cannot do is recorded as
  **a flag with that reason** (`remote: "unsupported"`), so nothing ever looks hidden that is not.
- **The message carries the state.** `message.moderation` (data-model.md: the one mutable part of a
  message) holds `action` (hide / flag / unhide), `remote` (hidden / pending / failed / unsupported /
  none), the network's note, the reason, and who asked (rule or person). `conversation.moderated_at` is
  the newest moderation on the thread and is null once nothing is in force — the Flagged tab's one
  definition.
- **The network call is a job.** `inbox.moderate { messageId, hide }` (worker
  `inbox-moderate.ts`) calls `adapter.hideItem`; every network that offers it sets a state, so a retry is
  safe. Retryable errors retry up to 3 times; anything else is recorded as `failed` in the network's
  words and the requester (person, else the rule's creator) gets an `inbox.hide_failed` notice.
- **A draft is a draft.** `inbox.draft_reply` writes a saved reply as a `draft` message (the same row the
  public API's reply-draft makes); a person presses Send. It never queues, never calls a provider.

## Networks

| Network | Hide | How | Source |
|---|---|---|---|
| Facebook Page | yes | `POST /{comment-id}?is_hidden=true` | Graph API Comment reference |
| Instagram | yes | `POST /{ig-comment-id}?hide=true` | IG Comment reference |
| Threads | yes | `POST /{reply-id}/manage_reply?hide=true` (hides nested replies too) | Threads reply management |
| YouTube | yes* | `comments.setModerationStatus` → `heldForReview`; `published` puts it back | Data API v3 |
| X | yes | `PUT /2/tweets/{id}/hidden` — replies to own posts; scope `tweet.moderate.write` (now in the default grant; older connections say why until reconnected) | X API v2 |
| LinkedIn, TikTok, Pinterest, Google Business, Bluesky | no | recorded reason in `HIDE_SUPPORT` | — |

\* YouTube has no hide; held-for-review takes the comment out of public view, and the row says so.

## Definitions the builder shows

- `has_link` — the text contains `http(s)://`, `www.`, or a bare domain with a common ending (the domain
  of an e-mail address does not count). `link_hosts` — those hosts, lower-case, without `www.`.
- `language` — ISO 639-1 code from tinyld; blank when there are fewer than 12 letters, because a guess is
  worse than "not sure".
- `prior_moderations` — this contact's OTHER inbound messages hidden or flagged right now. A flag a person
  cleared, or a comment shown again, was their decision and no longer counts.
- `prior_messages` — inbound messages from this contact to this workspace before this one.
- `has_any` — any of a comma-separated list of words or phrases, whole words, case-insensitive (the same
  matcher as the brand lint).

## Left out on purpose

- AI-written drafts by rule: the AI client is server-only and rules run in the worker; a saved reply is
  the draft a rule can make. AI suggestions stay in the composer.
- Deleting a comment at the network, and blocking a contact: neither is reversible from here.
- TikTok and Bluesky hides: TikTok's comment-hide endpoint is not in the API this adapter uses, and
  Bluesky needs thread-gate management; both are recorded as "not yet", not "impossible".

## Live check (2026-09-06)

`apps/platform/e2e/.state/moderation-live/` (git-ignored): fresh tenant, demo network, one saved reply,
two rules made in the builder — "Hide link spam" (`has_link` is true → hide, reason "Link spam") and
"Draft the refund answer" (`text has_any refund, chargeback` → draft the saved reply). Items were pushed
through the real webhook → worker path with the inbox's demo tools.

- A comment with a link: the rule matched, `inbox.moderate` ran, the demo network hid it; the message
  reads "⊘ Hidden on Demo network · Link spam — rule “Hide link spam”", the Flagged tab counts 1, the
  contact shows "1 message hidden or flagged now", the activity list shows Hide requested → Applied by
  rule → Comment hidden. **Show again** put it back through the network and cleared the tab.
- **Flag** by hand → "⚑ Flagged · Flagged by Moderation Tester"; **Clear flag** removed it.
- A DM with a link: the rule fired, the network cannot hide a DM, so the row reads "⚑ Flagged — could
  not hide · A direct message has no audience, so there is nothing to hide it from."
- A refund comment: the saved reply sits in the thread as "Draft — not sent" with a Send button; the
  rule's run says "drafted the saved reply … for a person to send".
- **Hide** by hand on a comment the demo network refuses: "⚠ Not hidden on Demo network · The demo
  network refused to hide this comment." with Try again / Clear, and one `inbox.hide_failed` notice.
- The inbox header's "Moderation rules" opens Settings › Automations, where both rules list their runs.

Found on the way: an item the demo network delivers by webhook was unknown to its own store, so a hide
