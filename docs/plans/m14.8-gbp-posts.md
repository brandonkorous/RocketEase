# M14.8 — Google Business Profile posts

**Status:** built and verified on the dev server up to the network call, 2026-09-06 (see the end of this
file). No new screen: a location is one more channel in Create (`images/create-post.png`), with its own
settings under "Customize by platform", so no mockup was needed. Google's API itself could not be called:
the `rocketease` Cloud project has a Business Profile quota of 0 until Google approves the access request
(memory: google-cloud-rocketease-project); the HTTP shape is covered by tests instead.

## What it is

A Business Profile location, until now connected for reviews only, takes posts: an **update**, an
**event** or an **offer**, with one photo and one button. The adapter publishes them as `localPosts`,
reconciles an ambiguous create, and reads a post's state back.

## What Google actually says (verified 2026-09-06)

| Thing | Google's words | Source |
|---|---|---|
| Endpoint | `POST https://mybusiness.googleapis.com/v4/{parent=accounts/*/locations/*}/localPosts`; get, list, patch, delete alongside | accounts.locations.localPosts reference |
| Post types | `STANDARD`, `EVENT`, `OFFER` (`ALERT` is Google's own); event details "Required for EVENT and OFFER topic types" | LocalPost reference |
| Buttons | `BOOK`, `ORDER`, `SHOP`, `LEARN_MORE`, `SIGN_UP`, `CALL`; the url "should be left unset for Call CTA" | CallToAction reference |
| Event | `title` + `schedule { startDate, startTime, endDate, endTime }` as Date / TimeOfDay objects, no zone | LocalPostEvent, TimeInterval |
| Offer | `couponCode`, `redeemOnlineUrl`, `termsConditions`, all optional; an offer also needs the event's title and dates | LocalPostOffer; Business Profile Help ("Offers … require a title, dates, and time") |
| Media | "sourceUrl is the only supported data field for a LocalPost MediaItem"; examples show `PHOTO` only | LocalPost reference, posts-data guide |
| State | `LIVE`, `PROCESSING`, `SCHEDULED`, `REJECTED`, `RECURRING` | LocalPostState |
| Lifetime | "Posts older than 6 months are archived unless a date range is set" | Business Profile Help |
| Photo | JPG or PNG, 10 KB to 5 MB, at least 250 px a side, 720 px recommended | Business Profile Help (photo guideline) |
| Text | Google's post editor refuses text over 1,500 characters ("Enter details no longer than 1500 characters"); the API reference publishes no number | Business Profile community threads quoting the editor |
| Not published by Google | how many photos a post takes; an event title length; whether local posts take video | — |

## Decisions

- **Every limit says where it came from.** `LIMITS` in `client.ts` carries the 1,500 characters, the one
  photo and the 5 MB, each with its source; the reasons the channel shows repeat them. Where Google
  publishes nothing (photos per post, video), RocketEase takes the conservative side — one photo, no
  video — and says so as its own choice, not Google's.
- **The post's settings live on the variant** (`post_variant.settings`, read through `GbpPostSettings`):
  type, button and its link, event title and dates, offer coupon/redeem link/terms, language. Dates are the
  location's own calendar and times are "HH:mm", because Google takes them without a zone. No button
  chosen and a post link present → a **Learn more** button with that link, so a link is never lost.
- **One validator for the composer and the worker.** `postIssues` (posts.ts) says what Google's editor
  requires — text or a photo; a title and dates for an event or an offer; a link for every button but
  Call; no end before start; photos only — after the shared capability validator has applied the 1,500
  characters and the one-photo rule. The composer shows the issues through autosave; the worker refuses
  the same post before it calls Google.
- **A rejected post is a policy failure.** The create call answers with the post's state; `REJECTED`
  becomes a `policy` error (not retried), never a success with a hidden post. `publicationStatus` reads
  `LIVE` as published, `PROCESSING`/`SCHEDULED` as processing, a missing post as deleted, and `REJECTED` as
  unknown — the platform has no rejected state for a publication yet.
- **Reconciliation without a marker.** Google gives a post no client reference. The attempt's text and
  start time are remembered in the process, and an ambiguous create is settled by scanning the location's
  newest posts for the same text at or after the attempt, never by resending.
- **Existing locations catch up on the next channel sync.** Capabilities are stored on the channel row
  and rewritten by `channel.sync`, so a location connected before this change stays reviews-only until it
  syncs; nothing needs reconnecting.

## Definitions the product shows

- **Post type** — Update (plain), Event (title and dates), Offer (title, dates, and optional coupon,
  redeem link and terms). Google keeps an event or an offer until its end date, and archives an update
  after 6 months.
- **Button** — one per post, with its link; the link is the post link unless another is given. Call now
  uses the location's phone number.

## Left out on purpose

- Calling Google for real: the project's Business Profile quota is 0 until Google approves access.
- Video in posts: Google documents photos only for local post media.
- Editing or deleting a live post from RocketEase (`PATCH`/`DELETE` exist): a later step, with the
  publication reconcile that would go with it.
- The Performance API for post metrics: a separate product; the channel says so.

## Live check (2026-09-06)

`apps/platform/e2e/.state/gbp-posts-live/` (git-ignored): fresh tenant, then a Business Profile location
seeded with the adapter's real capabilities on a sealed fake connection (Google's API is not reachable:
quota 0). Everything up to the network call was exercised in the browser:

- Create lists the location as a publishable channel, selected by default; "Customize by platform" shows
  its tab with the post settings panel and Google's 6-month archive note.
- Post type "Event" with nothing else: autosave runs the adapter's validation and the panel reads "An event
  needs a title." and "An event needs a start date and an end date." (the same lines appear in the
  destination panel's validation summary).
- Title, dates and times clear them; a "Book" button without a link reads "A “Book” button needs a link:
  give it one, or add a post link." and a link clears it.
- The saved variant is a valid `text` post with `settings` = event title, dates, times, topic `EVENT`,
  button `BOOK` + link, and no issues. Reopening the draft restores the panel with the same values.
- "Offer" adds coupon code, redeem link and terms.

Found on the way: right after a clean restart the signup page can serve a broken chunk on its first
paint (browser "Invalid or unexpected token", no form); fetching `/signup` and `/login` two or three
times with a pause before Playwright starts avoids it.

Tests: 9 new on providers (`posts.test.ts`: body, validation, publish, rejected post, reconcile, status)
and the adapter surface test updated; 242 provider and 1040 platform tests pass; typecheck clean.
