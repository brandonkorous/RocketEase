# M14.9 — Canva import

**Status:** built and verified on the dev server against a local stand-in for Canva's API, 2026-09-06
(see the end of this file). No new screen: a button and a dialog on the library (`images/library.png`
territory), so no mockup was needed. Canva itself was not called: RocketEase has no Canva integration
credentials yet (a launch chore, below).

## The decision the plan asked for (M12 §12: Canva Connect API vs Adobe Express embed)

**Canva Connect API now; Adobe Express later, through the same shape.** Recorded here and in
`docs/media-generation.md` §12.

- The deliverable is "Import from Canva into the library". Canva's Connect API lists the designs a person
  already has (`GET /rest/v1/designs`) and renders them server-side (`POST /rest/v1/exports`, one URL per
  page, PNG lossless or JPG). That fits the worker/job model, keeps a provenance chain, and needs no code in
  the browser beyond a button.
- Adobe Express has no API that lists or exports a person's existing designs; its Embed SDK runs the Express
  editor inside our page and hands back a rendered file when the person presses publish. That is a
  different feature (design inside RocketEase), with a client id, an allow-listed domain and a browser-side
  flow. When it comes, it writes assets through the same `import_source` + provenance shape.
- The other half of §12 — Canva as an export target through brand-template autofill — needs Canva
  Enterprise and is not what people asked for; import first.

## What Canva actually says (verified 2026-09-06)

| Thing | Canva's words | Source |
|---|---|---|
| Auth | OAuth 2.0 authorization code with PKCE (S256) at `https://www.canva.com/api/oauth/authorize`; token at `POST /rest/v1/oauth/token` with basic auth `{client id}:{client secret}` and a form body; not callable from a browser | canva.dev › Authentication |
| Tokens | access tokens "are only valid for a short period of time" — 4 hours today, "subject to change"; "Each refresh token can only be used once" and returns a new pair | Authentication; Generate an access token |
| Scopes | `design:meta:read` (list), `design:content:read` (export), `profile:read` (display name); scopes are explicit, `asset:write` does not imply `asset:read` | Scopes appendix |
| List | `GET /rest/v1/designs?query&continuation&ownership&sort_by`; 100 requests a minute per user; continuation token paging | List designs |
| Export | `POST /rest/v1/exports { design_id, format }` → job `in_progress` / `success` / `failed`, urls valid 24 h, "a download URL for each page in the design"; PNG `lossless`, JPG `quality` 1–100, MP4 needs a `quality` such as `horizontal_1080p` / `vertical_1080p`; 20 a minute per user | Create / Get design export job |
| Who may connect | a **private** integration serves the team on Canva Enterprise only; a **public** one must pass Canva's review (login for testing, a video, a questionnaire) before all Canva users can connect | Submitting integrations for review |

## Decisions

- **A source belongs to a person, inside a workspace.** Canva tokens are per Canva user, so
  `import_source` (migration 0032) is unique on (workspace, kind, member); the dialog says whose Canva it
  is and lets that person disconnect. Anyone who can add to the library can connect their own.
- **Read-only at Canva.** Three scopes, none that write. The dialog says so.
- **Refresh under a lock.** A Canva refresh token is single-use, so `accessTokenFor` locks the row, refreshes
  when less than two minutes remain, and writes the new pair before anyone else can read the old one. A
  refused refresh marks the source `action_required` and the person reconnects; nothing loops.
- **Each page becomes one image, in page order.** The action reserves one `pending` asset row per page
  (at most 10, the carousel ceiling), then the `import.canva` job exports once, waits (about a minute, then
  retries with a fresh export), downloads each page into its row's own object key, and hands the row to
  `asset.process` like an upload. A page Canva did not return, or an export Canva failed, marks its rows
  `failed` in Canva's words; nothing stays `pending` for ever.
- **Rights and provenance.** `license_source = owned` (the person made the design), `rights_note` names
  the design and the Canva account, and `provenance.chain` records `import_requested` (design id) then
  `imported` (export job id, page n of m, format). C2PA is `absent`: a Canva export carries no credential
  we could keep.
- **Paging, not load-more.** Canva pages with a continuation token only, so the dialog has Previous / Next
  page over a stack of tokens.
- **Video waits.** An MP4 export needs an orientation and size Canva must be told; until the design's
  dimensions are read first, the dialog offers PNG and JPG.

## Launch chore (yours)

Create the Connect integration at canva.dev (scopes above, redirect `https://app.rocketease.com/api/import/canva/callback`),
put its id and secret in Key Vault as `CANVA_CLIENT_ID` / `CANVA_CLIENT_SECRET`, and submit it for review
so people outside the team can connect. Until then only your own Canva team can use it (and only on
Enterprise, per Canva).

## Left out on purpose

- Adobe Express: a browser-side editor embed, a separate step; it will reuse `import_source` and the chain.
- MP4 export: needs the design's orientation read first (Canva's `quality` values are per orientation).
- Canva as an export target (brand-template autofill): needs Canva Enterprise; not asked for.
- Importing someone else's connected account: a source is the connecting person's own.

## Live check (2026-09-06)

`apps/platform/e2e/.state/canva-live/` (git-ignored): `stub.ts` stands in for Canva's API on :5099
(token refresh, profile, designs with a continuation page, an export job that answers `in_progress` twice
then `success` with one URL per page, and the page files); the dev server ran with
`CANVA_API_BASE=http://localhost:5099` and a media-role worker alongside the general one. A fresh tenant
got a Canva source seeded with a token 30 seconds from lapsing.

- The library shows "Import from Canva"; the dialog names the account ("Stub Designer's Canva").
- The first listing refreshed the single-use token through the stand-in (`POST /oauth/token` with
  `rt-old`), then listed three designs newest first with page counts; Next / Previous page followed the
  continuation token; a search by title narrowed the list.
- Importing the two-page design queued `import.canva`; the worker created one export, polled it, wrote
  page 1 and page 2 into their own rows in order, and `asset.process` made both `ready` (1080×1080, scan
  clean). Each row: `license_source = owned`, rights note "Imported from Canva design “Spring sale
  carousel” (Stub Designer)", chain `import_requested` (design id) → `imported` (export job id, "page n
  of 2, exported as PNG"). The library shows "Spring sale carousel (1/2)" and "(2/2)".
- Disconnect set the source `disconnected`, kept both files, and the dialog offered "Connect your Canva
  account" again.

Found on the way: locally only the **general** worker runs (`pnpm dev`), and `asset.process` belongs to
the **media** role, so imports (and uploads) stay `processing` until `WORKER_ROLE=media pnpm exec tsx
worker/index.ts` runs too — worth a second script in `pnpm dev`. `pnpm dev:kill` also kills any tsx
stand-in started from the repo. The "Canva connected" toast after the OAuth redirect was not caught by
the automated run (it fades before a slow first paint finishes); the button and dialog were.

Tests: 7 new on the Canva client (`lib/import/canva.test.ts`); 1055 platform tests pass; typecheck clean.
